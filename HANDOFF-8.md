Смена стратегии. Раньше (ветки `mobile-first` и ниже) переворачивали desktop-first
→ mobile-first **один-в-один**. Это плодило костыли (сохраняли кривизну легаси:
рассинхрон брейков, мёртвые правила, врущие комменты). Заказчик решил **собирать
презентационный слой заново** по макетам, чисто, fluid, на единых брейках.

## 1. Модель рерайта (согласована)

- **Не greenfield.** Ветка `rebuild` заведена от `mobile-first` — в ней уже ВСЁ
  (админка, данные, логика, анимации, токены, примитивы). Переписываем **только
  layout-CSS + разметку**; начинку не трогаем.
- **Локально**, не запушено. Старая ветка `mobile-first` = живой референс.
- **Fluid между брейками** (не дискретные тиры): каждое свойство плавно
  интерполируется `clamp()` от значения на нижнем артборде к верхнему. Это то, что
  заказчик называл «растягивается от нижнего до верхнего брейка» (≈ Tilda autoscale,
  но по каждому свойству точно).
- **8 артбордов:** `390 / 480 / 640 / 768 / 960 / 1200 / 1536 / 1920`. И 1536→1920
  тоже fluid (заказчик отдельно подчеркнул 1920).
- **Числа-якоря:** берём из текущего (в основном верного) кода + точечно сверяем с
  Figma. Заново из Figma тянем только там, где старое явно кривое.
- **Проверка — замерами** в браузере (`getComputedStyle`/`getBoundingClientRect`)
  на всех 8 артбордах, плюс «нет горизонтального скролла». Не на глаз.

## 2. Референс старого кода

- Папка **`reference/`** = копия `app/ components/ styles/` (как было). Уже создана.
  **В `.gitignore` + `tsconfig.exclude`** — в сборку/гит не попадает, удалим в конце.
- «Сделай как было» → читаю оттуда (или `git show mobile-first:path`).
- **Анимации почти бесплатны:** переносим старую логику (хуки/JS/keyframes),
  перевешиваем на новую разметку, а не переписываем.

## 3. Изоляция (чтобы новое не смешалось со старым)

1. Новые **уникальные классы**, свои у страницы. Старые (`ti-*`, `about__*`,
   `contacts__*`) в новой разметке не рендерятся → чужие правила не прилипают.
2. Новая страница **НЕ импортит** `home.css` / `trade-in.css`. Только глобальный
   слой + свой CSS.
3. **Не редактируем общие СТАРЫЕ файлы, пока на них висят страницы.** Старый файл
   доживает, пока им кто-то пользуется, в конце — `rm`. Никаких `-2` в именах.
4. Дизайн-система остаётся общей (токены, шрифты, `Button/Badge/Crumbs/LeadModal`,
   иконки, `GlassSurface`) — это фундамент, не дублируем.

## 4. Что УЖЕ сделано на `rebuild`

### Токен `--gutter` (единый боковой отступ контента) — `styles/tokens.css` (в конце)
Кусочно-fluid по 8 точкам, **контентный, кап 60**:
`390→20 480→20 640→30 768→40 960→40 1200→40 1536→60 1920→60`.
Старый `--page-gutter` НЕ тронут (уйдёт при рерайте страниц). Реализован сегментами
через `@media (min-width: …)` + `clamp`.

### Шапка — `components/layout/header.css` (новый файл), коммит `dce0c95`
- Вынесена из свалки `layout.css` (там теперь **только футер + мобильное меню +
  мега-услуги**). `Header.tsx` импортит `header.css` + `layout.css`.
- **Разметку и логику `Header.tsx` сохранил** (ссылки `/about /contacts /catalog /`
  `tel:+74997041444`, scroll-headroom `useHideOnScroll`, копирование телефона+Alert,
  состояние дропдауна услуг). Переиспользуются как есть: `GlassSurface` (стекло),
  `MobileMenu` (бургер-оверлей), `ServicesMega` (дропдаун «Услуги»).
- Mobile-first, fluid на наших брейках. Верх **18px фикс**, бока = `--gutter`, бар
  центрируется (`max-width 1880`, `margin auto`).
- **Шапка ШИРЕ контента:** её боковой отступ падает `60→20` на 1536→1920
  (переопределён `padding-left/right` в блоке `@media (min-width:1536px)` внутри
  header.css). Контентный `--gutter` при этом капается на 60.
- Числа из Figma, **сверено замерами один-в-один** (высота бара 58/66/78, лого
  201/275/241/273/336, бургер/контрол 36/44/46, CTA size L на 1920).
- **nav↔бургер переключаются на 1200**: ≥1200 — nav слева + лого центр + [звонок][Каталог];
  ≤960 — лого слева + бургер.

### Крошки — `styles/components.css` (`.ui-crumbs`), коммит `7eba701`
- Переписаны чисто, mobile-first fluid: шрифт `10 (390) → 14 (480+)`, шеврон `8 → 12`,
  нижний зазор единый **20**. Убраны конфликтующие `margin-bottom` (10/6/2) и
  max-width-костыли.
- Вертикальный ритм — единая fluid-формула (`styles/tokens.css`):
  - `--header-h` = 18 + бар = `76 → 84 → 96` (fluid, синхронно с header.css);
  - `--crumbs-gap-top` = `40 (390) → 50 (480…1536) → 60 (1920)` (fluid);
  - `--page-top = --header-h + --crumbs-gap-top`;
  - `--crumbs-page-top = var(--page-top)` — **легаси-матрица (106/134/156) убрана**.
- **Левый отступ крошек = гутер КОНТЕЙНЕРА страницы.** На старых страницах контейнер
  ещё на `--page-gutter`, поэтому крошки слева не совпадают с шапкой (заказчик это
  заметил — это норм). Сойдётся с `--gutter`, когда перепишем страницу.
- Сверено на trade-in (390/480/730/1536/1920): зазор 40/50/60, шрифт 10/14, на 1920
  край шапки 20 vs край крошек 60 — по макету, скролла нет.
